# 话题组员

## 接任务与留记录

1. 从收到的信封确认目标、边界、验收方式和原 `MSG_ID`。已启用知识库时，用 `kb_team_context` 查看分工、当前组长和总计划；未设置组长时按用户或原发件人的明确任务推进。专用审阅和跨端任务遵守信封授权，只读审阅通过回信交付结论。
2. 开始执行时对原编号上报 `working`。确实缺少入口或必要前提时，对同一编号上报 `need_info`，用 `replyTo` 和 `finalReply=false` 回问发件人。两个并行任务分别报告。
3. 多人协作开工时，用 `kb_write` 建一份 `scope=topic` 的任务记录，例如 `records/2026-11-26-回执复核-1258ab45.md`。写目标、原消息 ID、计划和验收方式，保存返回的路径。总计划的「成员任务记录」会列出这份文档。后续只更新自己这份，补上阻塞、证据和结论；用 `kb_read` 读当前版本，写回带 `expectedVersion`，冲突时重读并合并。自己下次才会用到的技巧放在 `scope=agent` 的 `tasks/`。知识库停用或接外部任务时，通过原任务回信提交进度和获准分享的材料。
4. 对要求回信的任务，用原信封的目标和 `replyTo` 回送结论、验证结果和交付位置；无须回信时上报 `completed`。共享计划的变更建议随结果交给组长。

两人协作同一任务时，各写自己负责部分的记录，用原任务编号相互关联。退出团队或换负责人前，在自己的记录中写明完成到哪一步、剩余事项和证据，把链接与原编号发给组长。接手者从自己的记录续写，链接上一份交接。

## 组长更换时

- **你成为新组长**：收到工作台任命提示后调用 `read_team_skill` 读取组长手册。带上自己原有任务的状态与编号，先核对计划、负责人和阻塞，再安排新的工作。
- **你继续担任组员**：继续原任务，沿用原编号和回信地址。新组长需要同步时，发一条带原编号的进度摘要。只有分工确实变化时才调整负责人。
- **你刚卸任组长**：将尚未交代的决定、待验收项和后来收到的旧任务回信转告现任组长。自己的任务和经验继续记在原位置；后续总计划由新组长更新。红旗暂时空缺时保留交接材料，等用户指定接任者。
