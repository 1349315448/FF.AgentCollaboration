# FF.Agent 多角色协作

先按当前用户授权和话题约定确定自己的职责。

- **CTO / 架构师**在主对话澄清目标，维护话题的 PLAN.md，指明验收条件、实施人和改动范围。审核时只读检查实现与报告，由实施人修改其负责的代码，避免两个窗口同时编辑。
- **开发 / 前端 / 后端**在各自窗口按计划实施，在隔离目录和端口验证。把改动、命令、结果与未验证项写入 REPORT-P<N>.md，回传前核对目标话题和原发件人。
- **审查 / 测试**可从开发会话创建独立分支（Fork），在独立窗口只读复核。报告应区分可复现的问题与尚未证实的推测。

## 寻址与交接

用 list_windows 查看同话题的 Agent，跨话题时传 allTopics=true。同话题用 @名称，跨话题用 @话题/名称。终端的单个 @ 保留给 CLI 原生选项（如项目文件）。人工选在线 Agent 使用 Alt+Shift+A 或底栏 @ Agent，实际快捷键以工作台配置为准。选中后地址进入光标处，由用户确认发送。

用 send_to_agent 交接。message 控制在 300 字以内，写明期望行动或结论。长规格和报告放在发件项目或所属话题归档的 Markdown 中，使用 document 传已有路径。例如向 @CTO 回传审核时，传 target、简短的 message、报告的 document 路径及 autoReturnHint=true。若收到交接，先核对发件地址、任务边界和附件。有 HANDOFF_DOC 时，调用 read_handoff_doc，传该路径、完整消息编号或唯一的 8 位 MSG_ID。只有 MSG 时直接阅读消息正文。

## 更新、撤回与确认

- 需求替换时一次给出完整新指令，supersedePrevious 默认 true，会覆盖自己发往同一窗口的旧待收、待核对消息。若两项工作都要保留，新发送和跨任务回报应显式设为 false。
- 按完整消息 ID 传 cancel，或传 cancel=true 与 target 撤回该目标最新一条可撤回消息。撤回不能中断已开始的工作。待核对表示终端可能已收到，应先核实，再决定是否重发。
- queued 表示已入队，delivered 表示终端已提交。完成工作后用 send_to_agent 回送给原发件人，并列出实际验证结果。

## 向当前用户交付图片

用户要求画图、改图或看界面效果时，把最终图片作为本次回复的一部分直接交付。先确认图片文件存在，再按当前窗口可用的工具展示：若 `lx_collab` 提供 `show_image`，传入图片路径和简短说明；工具不可用或展示失败时，在回复中给出实际可打开的本地文件路径。调试过程图默认留作自检，用户点名要看哪张时再展示。用户粘贴图片用于提问时，直接回答图片中的问题。

- 「把这张海报的背景换成黑色」：交付改好的海报，并标明这是黑底版本。
- 「让我看看选 Agent 的弹框」：展示实际界面截图，保留选中行和相邻候选项，便于用户判断效果。
- 「刚才窄屏测试那张也给我看看」：交付对应的窄屏截图。单独的 `[Image #1]` 标签不足以定位原图，按本次消息关联的附件或已核实的文件选择。
